DESIGN DECISION worth flagging: your spec's POST /api/inspections line says "protected, any authenticated tenant," but test-plan item 4 in your own instructions ("confirm a tenant cannot request an inspection on their own property, if they're also a landlord elsewhere") only makes sense if the backend doesn't actually gate on profile.role==='tenant' — a landlord/agent account needs to be ALLOWED to call this endpoint so the ownership check can correctly block them on their own listing. So I implemented POST with no role restriction at all (any authenticated user, blocked purely by the owner_id comparison), and put the role restriction only on the FRONTEND button's visibility (RequestInspectionButton only renders for profile.role === 'tenant', per the frontend spec's explicit wording). This means a landlord CAN technically call the API directly to request an inspection on someone else's listing even though the button never shows for them — flag if you'd rather the backend also hard-block non-tenant roles.
